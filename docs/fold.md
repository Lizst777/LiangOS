# Fold：功能与实现说明

运行开发服务，打开 `http://127.0.0.1:5173/`。

Fold 现在是唯一页面，`npm run build` 输出 `dist/`。示例图片由 Vite 收集，视频编码器保持按需加载；构建不使用旧站环境配置。

## 当前范围

- 上传本地 JPG、PNG、WebP、AVIF；拖动裁切、缩放。
- 编辑标题、副标题、署名；切换纸色及 3:4、1:1、9:16 比例。
- 副标题在固定区域内自动排为一至两行，优先保留字号；中英文长句完整保留，预览与导出共用排版。
- 预览右下角“放大查看”打开只读纸面：正反面切换、适应画面及两倍放大滚动。打开时暂停动画，关闭后保留进度与编辑内容，不增加撤销记录。
- 10 秒完整循环：收拢封面、外页先开、内页展开、正面停留、翻面署名、合拢回环。
- 四个分镜快捷入口、播放/暂停、进度拖动与轻微镜头动势；编辑时平滑展开正面。
- PNG 输出平展海报；视频输出同一渲染器中的折页场景。
- 视频按固定时间线逐帧编码：300 帧、30 fps、精确 10 秒，生成耗时不改变作品时长。
- 按当前画幅检测 H.264/MP4 编码能力，不支持时检测 VP9/WebM；均不可用时保留 PNG，不退回不稳定的实时录制。
- 图片不上传服务器。通过 IndexedDB 自动保留一份本机草稿，恢复图片、文字、裁切、比例、纸色和镜头动势。
- 撤销/重做支持按钮、Ctrl/⌘ Z、Ctrl Y、Ctrl/⌘ Shift Z；短时间连续输入合并，一次拖动算一步。
- 新建需确认，且可在当前会话中撤销。刷新只恢复当前作品，不恢复撤销历史。
- 进入后台暂停预览；编码中进入后台或关闭导出框则取消并释放编码资源。
- 每帧等待编码器接收后才继续，进度显示实际帧数。封装完成后核验编码帧数；异常或超时不会输出不完整文件。

当前版本尚无多作品管理、直接点击画布编辑文字、其他动画风格。真实 iPhone/Safari 的软键盘、存储和编码兼容性仍需要设备验收。

### 小屏编辑

- 竖屏上方保留预览和播放控制，下方为“图片 / 文字 / 样式”三个设置分组；只在设置内容内部滚动，预览不跟随离屏。
- 默认打开文字；样式包括比例、纸色和镜头动势。撤销、重做、新建与草稿状态始终位于设置面板上方。
- 各分组复用同一套输入控件，切换只改变可见性，不复制数据、不创建撤销步骤、不重置作品。
- 桌面展开所有设置；手机横屏使用左右分区。较窄屏幕的样式控件改为单列，避免挤小纸色按钮。
- 标签支持方向键、Home、End；窗口尺寸变化不会把焦点留在隐藏控件上。
- 使用 VisualViewport 的可见高度适配键盘占用，并保留安全区域；放大手势不锁定在缩小后的视口高度。真实 iOS 键盘仍待实机验收。
- 分组选择不写入草稿；刷新恢复作品后，小屏从文字分组开始。

### 草稿边界

- 不使用 localStorage，不上传文件。草稿按当前浏览器和站点地址隔离，本地与线上、localhost 与 127.0.0.1 不共享草稿。
- 内容和图片在同一事务中提交。文字编辑不重复写图片；保存请求串行执行，只合并尚未写入的中间状态。
- 界面只有在事务完成后才显示已保存；失败或冲突时显示未保存，存在未保存内容时尝试阻止直接离页。浏览器崩溃或强制结束进程仍可能丢失尚未完成的写入。
- 多标签页使用版本检查，旧页面不能覆盖另一页刚保存的内容。遇到冲突，先导出需要保留的作品，再刷新。
- 读取损坏或不支持的草稿时不覆盖原记录；此时当前编辑不能自动保存，需要先导出并重新打开页面。
- 历史最多保留 40 个状态、64 MB 独立图片文件引用；不复制每一步的图片像素。只为当前画面保留解码位图。
- 清除网站数据、无痕会话结束或浏览器回收存储都可能删除草稿，因此它不是永久备份。

测试位于 `test/fold*.test.mjs`。编码依赖锁定为 `mediabunny@1.55.7`，只在打开导出对话框时动态加载。

`texture-mesh.js` 单独负责三角网格贴图及接缝覆盖，避免逐行绘制的横纹。

### 维护边界

- 表单只更新作品内容，动画控制器只读取内容；不要把导出状态放进作品数据。
- 预览只使用一个动画帧调度入口，播放、暂停和编辑展开相互切换，不并行叠加。
- 导出框打开时取得一次作品快照；关闭后使旧异步回调失效，并取消编码、释放结果 URL。
- 帧数和帧率来自 `frame-sequence.js`，时长来自 `geometry.js`，界面不另建一套计数。
- 图片及缩略图解码成功后才替换当前资源；过时请求和失败请求不能覆盖当前作品。
- 普通样式留在 CSS，几何计算留在纯函数，页面接线不建立通用事件总线或第二套状态框架。

## 累计验证

- 37 项 Fold 测试（原站 8 项测试随旧站归档）通过，覆盖字段校验、输入/拖动分组、历史分支与内存上限、串行保存与失败重试、新建撤销、图片失败不改历史、无法读取的草稿不覆盖，以及面板切换、键盘导航、跨尺寸焦点和可见高度变化。`test/foldText.test.mjs` 另覆盖短句、64 字中文、英文单词与空文案的排版；`test/foldDetail.test.mjs` 覆盖放大尺寸、快照切面、重复打开复位与关闭资源释放。
- 本轮浏览器实测：文字与画幅刷新恢复；上传图片刷新恢复；换图撤销/重做；新建确认、取消与撤销；两标签页冲突拦截。
- Fold 是唯一构建入口；旧站代码已保留在 Git 检查点与本机备份中。
- 1280×720 桌面、390×844 移动端浏览器检查，无横向溢出。
- 实际替换本地图片、修改中文标题、拖动进度、切换画幅。
- 逐帧 MP4 已实际下载，播放器读取为 1080×1440、精确 10 秒，无解码错误。
- 对下载文件运行 `npm run verify:video -- <文件路径>`：确认 H.264、300 帧、30 fps、连续时间戳、10 秒。
- 9:16 竖屏也已实际导出、播放和解析：1080×1920、300 帧、30 fps、10 秒。
- 浏览器实测中途取消后可重新生成，无旧任务残留输出。
- 浏览器控制台无警告或错误。真实 iPhone/Safari 尚未验证。

## 导出设计依据

按照 [Mediabunny 的文件写入机制](https://mediabunny.dev/guide/writing-media-files)，通过 CanvasSource 为每帧指定时间戳和时长，等待编码背压后再提交下一帧，最终封装 MP4/WebM。时间线不读取墙上时钟、不使用 MediaRecorder 或 requestAnimationFrame 录制。

桌面端已验证。真实 iPhone/Safari 的编码支持和内存限制仍需设备验收；能力检测通过也可能因资源不足而编码失败，因此保留取消、失败及五分钟超时清理。未引入服务端上传、FFmpeg 或账号系统。
